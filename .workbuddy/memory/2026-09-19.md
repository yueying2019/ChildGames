## 第三次报错：AddressableContentBuilder CS0246（asmdef 拆分的连带账单）
`Assets/Scripts/Editor/AddressableContentBuilder.cs(669)` 找不到 `AddressableAssetSettings`。**不是拼写问题，是我自己加 asmdef 的连带后果**：Addressables 的编辑器 API（`UnityEditor.AddressableAssets.*`）不在 `Unity.Addressables` 里，而在独立程序集 **`Unity.Addressables.Editor`**（路径 Library/PackageCache/com.unity.addressables@1.22.4-t1/Editor/Unity.Addressables.Editor.asmdef 可查）。已在 SmallGames.Editor.asmdef 的 references 补上。**规则：代码一旦脱离 Assembly-CSharp，包的 assembly 引用要逐个显式补；Runtime 侧要补 Unity.Addressables/Unity.ResourceManager，Editor 侧还要补 Unity.Addressables.Editor。**

随后把同类型的拆分连带风险一次性扫完（结论：干净）：
- Runtime 里 10 处 `#if UNITY_EDITOR`（UIStyle:58 / GameBootstrap:208 / AssetHub:734,781 / AudioManager:155 / ResultPanel:132 / Match3LevelCatalog:76 / SheepLevelCatalog:133 / LianliankanLevelCatalog:123 / Card378QLevelCatalog:110 / AddressableCdnPaths:37,62）只用 `AssetDatabase`/`EditorPrefs`/`EditorApplication`，全在 Unity 自带 UnityEditor.dll，且 Runtime 的 noEngineReferences=false，Editor 平台自动链接 → **Runtime asmdef 不需要也不能加 Unity.Addressables.Editor**（该 assembly 仅 Editor 存在，加进全平台程序集会导致真机构建失败）。
- 跨程序集 internal 访问：全项目只有 UITween.TweenHandle 的字段和 UIPanel.Bind 两处 internal，均在 Runtime 内部使用，Editor 脚本无涉 → 无 CS0122。
