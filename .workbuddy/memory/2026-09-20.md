## 每日任务面板：任务行挂错父节点

顺带确认的 UGUI 参数：`childControlHeight=false` 时 LayoutGroup 用 `child.sizeDelta.y` 求和，行高能保住；`childControlWidth=true` 必须配 `childForceExpandWidth=true`，否则行宽被 clamp 到 Text 的 preferredWidth。

## 378Q 每日任务「打出 2 次 378Q」完不成
根因：`Card378QGameView.PlaySelected()` 写成 `if (_engine.TryPlay(_engine.CurrentSeat, ...)) { AfterAct(_engine.CurrentSeat, true); }`，而 **`TryPlay` 内部第 177 行已经把 `CurrentSeat = NextSeatWithCards(seat)` 改掉了**，所以 `AfterAct` 收到的是**下家**座位。`AnimatePlay(seat, play)` 里的 `local = IsLocalSeat(seat)` 恒为 false → 玩家的 378Q 一次都记不上。
修复：埋点改用 **`_engine.LastPlaySeat == LocalSeat`**（`TryPlay` 里 `LastPlaySeat = seat` 记的是真实出牌者，public 属性，AI 分支也走 TryPlay 所以同样可靠）。
**通用结论：在 378Q 里凡是"谁出的牌"，一律用 `_engine.LastPlaySeat`，不要用传入的 seat 参数。**
遗留（未改，需用户确认）：`PlaySelected` / `Pass` 这个传参错位是**项目原有**的，同样影响 `RememberAction`（1651 行把上家的出牌记到下家头上）、`PlaySfx`、`AnimatePlay` 的 `PlayedRootOf(seat)` 落点。修法是在调用 `TryPlay/TryPass` 之前先把 `var seat = _engine.CurrentSeat;` 存局部变量。因为会改变出牌动画的落点表现，没擅自改。

## 踩坑：并行 Edit 同一文件会丢改动
一次消息里发两条 `Edit` 指向**同一个文件**时，两条都基于编辑前的快照，后写覆盖先写 → 前一条静默丢失（本轮 MainMenuPanel 的 OnOpen/OnClose、UIManager 的 BackPriorities/HeavyPanels 都丢过）。
**规则：同一文件的多处修改必须串行，改完复读确认。**
写了个「类型→成员可访问性」扫描脚本（遍历 Assets/Scripts 建 typemap，正则抽 public/internal/private 成员，再核对 Assets/Tests 里的 `X.Y(` 调用）。结果：
- 命中真 bug 1 个（就是上面这个 PRIVATE）。
- **误报/漏报同样多**：① `Match3GoalType.Score` 报 MISSING —— enum 成员无修饰符，正则抓不到；② `Match3LevelData.Width/Height/ColorCount` 也漏 —— 声明带行内 `[Range(...)]` 特性，行首正则失配；③ `var x = ScriptableObject.CreateInstance<T>()` 这类泛型工厂无法推断变量类型，`x.XXX` 整段被跳过。
- **结论：这类脚本只能当"初筛 + 缩小人工核对范围"，不能当编译器。** 它保证不了零缺陷，真正兜底的还是"改完复读"和分批交付。

## asmdef 拆分后的引用约束（长期有效）
- Runtime 程序集（全平台）：只能引 `Unity.Addressables` + `Unity.ResourceManager`。**绝不能引 `Unity.Addressables.Editor`** —— 该程序集仅 Editor 存在，加进去真机构建会失败。
- Editor 程序集（includePlatforms=Editor）：三个都要引，含 `Unity.Addressables.Editor`，否则 `UnityEditor.AddressableAssets.AddressableAssetSettings` 报 CS0246。
- Runtime 内的 `#if UNITY_EDITOR` 只用 `AssetDatabase/EditorPrefs/EditorApplication` 是安全的（UnityEditor.dll 对 Editor 平台程序集自动链接，前提是 `noEngineReferences: false`）。
- 全项目 internal 仅 2 处（UITween.TweenHandle 字段、UIPanel.Bind），均在 Runtime 内部消费，无跨程序集访问。
