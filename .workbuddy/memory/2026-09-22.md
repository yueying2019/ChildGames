## 三消 / 对对消扩展点调研（用户问"另外两种玩法怎么出新道具、新玩法"）

### 三消 Match3
- 道具已 7 个（提示/重排/消除/横消/竖消/炸弹/加步），框架：`Match3GameView.Match3Tool` 枚举 + `_armed` + `ArmTool/OnTileTapped` 分发，加一个道具 = 加 enum + ShopItemId + CoinWallet 四处 + ArmTool 分支。
- 引擎现成入口：`TryRemoveAt(x,y)`（锤子）、`TryPaintSpecial(x,y,special)`（横/竖/炸弹）。**`TryPaintSpecial` 第 97 行显式拒绝 ColorBomb** —— 想出"彩球笔"只需放开这一行。
- 无"同色全消"入口：`ClearColor` 是 private（被 FireSpecial/ApplyColorBombCombo 用），要新增 public 包装。

### 对对消 Lianliankan
- 道具**只有 2 个**（重排/提示），是三个玩法里最空的（Sheep 4 个、Match3 7 个）。
- `AddTimerSeconds(float extra, float cap)` 已是 public → "加时"道具成本最低，只差按钮 + CoinWallet 注册。
- `SetTimerRunning(bool)` 已 public → "冻结"同理。
- `TryHint(out r0,c0,r1,c1,path)` + `PlayLink` 协程 → "自动连"（提示后自动消掉）可直接拼。
- **Blocker（障碍墙）是现成没用的能力**：`LianliankanEngine.Load(ids, blocked)` + `SearchPath` 里 `IsEmpty` 判 `_blocked`，墙真的挡路径；但 20 关内置 Spec 全是模板生成，没一个用 Blocker。`LianliankanLevelData.SetCell` 支持写 Blocker，`ApplyTemplate(kind, keepBlockers)` 也保留 → 障碍迷宫关是"零提审的新玩法"。
- 棋盘行列是 const 10×10（`LianliankanGameView.Rows/Columns`），改尺寸要动 const 与预制体。
- 路径 BFS 允许绕外圈一圈（`minR=-1, maxR=Rows`），最多 2 个拐弯。
- 其他可行变体：连锁回时（NoteCombo 里加秒）、塌陷模式（Clear 后重排 + 重新 Load，中等改动）。

## 事故：改写脚本写丢 Unity YAML 头部 → GameView 预制体全部加载失败（当晚修复）
现象（运行时两条报错成对出现）：
```
[UI] 缺少预制体 Lianliankan/LianliankanGameView
[AssetHub] 缺少资源 Lianliankan/LianliankanGameView
```
根因：**不是 Addressables 没登记，是预制体本身导入失败了**。`AssetHub.Load` 在 Addressables 查不到后会走编辑器兜底
`LoadFromEditor`（遍历 `Assets/Content/<key>.prefab`），兜底也返回 null → 只可能是 AssetDatabase 导入失败。
再查文件：Tools 里的改写脚本把文本文件按 `--- !u!<class> &<fileID>` 切块再 `join` 回去，**文件最前面两行指令被丢掉**：
```
%YAML 1.1
%TAG !u! tag:yousandi.cn,2023:      <- 团结引擎的 TAG，不是 unity3d.com
```
丢掉 `%TAG` 后 `!u!114` 无定义 → YAML 解析失败 → 资源当导入失败处理。

排查/修复套路（下次照做）：
1. 成对报错且编辑器兜底也失败 → 先怀疑「文件被改坏」，不是 Addressables。
2. 全量扫首行：`Assets` 下 172 个 .prefab/.asset 里只有 3 个 GameView 缺头（LevelSelect 那条脚本没这毛病，它保留了前缀）。
3. `Tools/repair_prefab_headers.py`：从 `Tools/_backup/*.bak` 取回前缀，并校验「当前块集合 ⊇ 备份块集合」（这次缺失 0，纯丢头）。
4. 悬空引用判据：fileID 位数 <= 8 的都是内置资源（12800000 默认字体 / 21300000 默认 sprite / 11500000 缺失脚本），
   不能算悬空；本次 Lianliankan 2 条、Match3/Sheep 各 1 条悬空**备份里就有**，是历史遗留非本次引入。

防复发（已落到代码里）：
- 四个改写脚本（add_sheep_slot_button / add_sheep_slot_frames / add_lianliankan_tool_buttons / add_match3_tool_buttons）
  的 `split_blocks` 改为返回 `(header, blocks)`，新增 `render(header, blocks)`，写盘前 `if not out.startswith("%YAML"): 拒绝写入`。
- `verify_new_tools.py` 加 %YAML/%TAG 头部检查。
- **任何用 Python 改写 Unity YAML 的脚本，必须保留并回写前两行指令。**

### 二次事故：fileID 超 Int64（同一批脚本的真实致命伤）
补完头部后 Unity 仍报 `InvalidKeyException: Key exists as Type=UnityEditor.BrokenPrefabAsset`。
**关键突破：直接读编辑器日志**（团结引擎日志在 `C:\Users\xtt\AppData\Local\Tuanjie\Editor\Editor.log`）：
```
Duplicate identifier 9223372036854775807. File: "Assets/Content/Lianliankan/LianliankanGameView.prefab".
Error loading the file '...'. File has multiple objects with same identifiers. Probably caused by a merge.
    -> AddressableAssetEntry.cs:946  Type BrokenPrefabAsset ... will be stripped and not included in the build
```
9223372036854775807 = `long.MaxValue`。**Unity fileID 是 SInt64**，而脚本里 `random.randint(10**18, 10**19-1)`
的上限 10^19-1 远超 Int64 最大值，那些 ID 被Unity 截断成同一个 long.MaxValue → 多对象撞 ID → 文件判损坏。
Lianliankan 撞 3 个、Sheep 撞 2 个、Match3 恰好 0 个（所以它后来没再报错），LevelSelect 也侥幸 0 个。

修复：`Tools/fix_out_of_range_ids.py`（扫 >Int64.MaxValue 的 fileID，块头+引用统一换到 `[10^17, 2^63-2]`）。
所有脚本的 ID 生成器统一改成 `random.randint(10 ** 17, (1 << 63) - 2)`；`verify_new_tools.py` 加越界检查。

### 方法论（本次最大收获）
1. **遇到资源加载失败先看 Editor.log**，里面往往有静态分析看不出来的具体原因（这次是 Duplicate identifier）。
   团结引擎日志在 `%LOCALAPPDATA%\Tuanjie\Editor\Editor.log`，Unity 在 `%LOCALAPPDATA%\Unity\Editor\Editor.log`。
2. 光做「结构/语义」校验不够——`Tools/audit_prefab_graph.py`（组件↔GO 互指、父子互指、重复挂载、重复子节点、
   环与可达性）跑出来全 0 问题，仍然 import 失败；**值域合法性（Int64）必须单独查**。
3. 日志里的 `CS0103 StarCatalog 不存在` 是会话初始 refresh 的过渡报错（新文件未纳入那次编译），
   后面 "Tundra requires additional run, N items updated" 即自愈，**不是真编译错误**。
