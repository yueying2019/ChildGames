## 玩法拓展方向咨询 → 落地 S1 星级评价

用户问「怎么在现有内容上拓展玩法」。核完三个玩法后给出的判断：**问题不在玩法本身，在缺"局间目标"和"社交对比"两层外壳**，因此不建议急着加第四个玩法（收益递减 + 六件套成本）。项目特有优势是 `mode_*` 三个 Addressables 分组走 Remote，关卡/活动内容可以绕过微信审核热更。

用户选了 S1（星级评价），已实现：

### 新增
- `Data/StarCatalog.cs`：3 星规则表。两套口径 —— `FromRemaining(float)`（剩余资源比例，三消/对对消用）与 `FromCombo(int)`（连击峰值，叠叠消用）。阈值写死为 const，刻意不放 GameBalance（它是 SO，走 Fallback 时新字段会是默认值 0，有除零风险）。

### 改动
- `ProgressRepository`：`ProgressData` 加 `List<int> LianStars/SheepStars/Match3Stars`（JsonUtility 支持 List 字段，不支持 Dictionary，这是选型原因）；新增 `Stars` / `RecordStars`（只升不降，返回是否刷新）/ `TotalStars`；`Clamp()` 里补 null 兜底防老存档。
- `GameSessionBase`：新增 `protected virtual int ComputeStars()`（默认 1 星），在 `ReportResult` 里 `isWin` 分支调用并写入存档、塞进 `ResultPayload.Stars`。**续关降星规则放基类统一处理**：`ContinuesUsed > 0` 时降 1 级保底 1 星 —— 金币能救命但买不到评级。
- 三个 Session override各自的口径：`Match3` 用 `MovesLeft / MoveLimit`；`Lianliankan` 用 `TimeLeft / TimeLimit`；`Sheep` 用 `ComboPeak`。
- `LianliankanGameView`：加 `TimeLeft` / `TimeLimit` 只读出口（`_timeLeft`/`_timeLimit` 原来是 private）。
- `SheepGameView`：加 `_comboPeak` 字段 + `ComboPeak` 出口，在 `_combo++` 后更新峰值、`StartPlay` 里重置。
- `ResultPanel`：`ApplyStars(bool win)` → `ApplyStars(int stars)`，部分点亮；评级文案接进 `MessageText`。
- `LevelSelectCellView` / `LevelSelectPanel`：`Bind` 加 `int stars` 参数，选关格子上显示历史星数；标题显示「玩法 X/Y 星」。
- `LevelSelect.prefab`：往 `Cell` 模板加了 Star1/Star2/Star3 三个 Image。

### 差点踩的坑（记录）
- **Sheep 通关条件是场上清零**（`SheepGameView` 里 `left == 0` 判胜），所以通关时槽位必然为空 —— 我最初打算用"槽位空余"评星，那是错的，读代码才发现，改成连击峰值。
- Unity YAML 脚本 `Tools/add_level_stars.py` 的 bug：定位锚点 `--- !u!224 &<id>` 那一行本身就以 `--- ` 开头，循环从 start 开始会第一轮就 break，必须从 `start + 1` 起扫。

### 工具

## 叠叠消新道具 + 规则层四字段（同日追加）

用户选了「暂存位道具」+「四同消除」，并把 `SlotBonus / TimeLimit / ComposeNum / GoalCount` 四个规则字段一次铺进 `SheepLevelData`。

### 设计判断（决定性的前提）
三个玩法的压力源不同，**道具清单不能照抄**：三消缺步数 → 道具给火力；对对消缺时间 → 道具给提示/加时；**叠叠消缺信息（`IsCovered` 遮挡）+ 点了不可逆 + 槽满即负没有一帧缓冲** → 道具该给「信息」和「缓冲」。

### 改动
- `SheepLevelData`：加 `SlotBonus` / `TimeLimit` / `GoalCount`（`ComposeNum` 已有）+ `DefaultCompose/MinCompose/MaxCompose/MaxSlotBonus/MaxTimeLimit` 常量 + `HasTimeLimit/HasGoal`。**旧 .asset 反序列化时新字段取默认值 0/3，完全向后兼容，20 个关卡不用重导。**
- `SheepGameView`：
  - 新增 `ApplyRules(config)` 一处把四个字段落到运行时状态（`_compose` / `_slotLimit` / `_timeLimit` / `_goalCount`）。
  - **解开 ComposeNum 硬编码**：`/3*3`、`%3`、`RestoreAndBalance` 里三次 `bag.Add(id)` 全部换成 `_compose` → 支持四同/多同变体。
  - `SlotCount` const 保留作基准值，改由实例字段 `_slotLimit` 参与判定（`OnTileClicked` / `CheckEnd`）。
  - 限时：`Update() → TickTimer()`，`InputLocked || _matching` 停表；显示复用 `DateText`（`RefreshHeader()` 只在整数秒变化时写 Text）。
  - 目标关：`CheckEnd` 里 `_groupsCleared >= _goalCount` 判胜，且**判定放在槽满之前**，避免「最后一组第三张刚落槽」被误判失败。
  - `TimedOut` 做成纯计算属性（`_timeLimit > 0 && _timeLeft <= 0`），不额外存状态。
  - 槽位自适应：`SyncSlotFrames()` + `SlotCellWidth()` + `BaseTileWidth/BaseTileHeight/SlotSpacing/SlotPadding` 常量。
- `SheepSession`：`OnLost` 按 `TimedOut` 区分失败文案；`ComputeStars` 限时关改走 `FromRemaining(TimeLeft/TimeLimit)`。
- 新增道具 `ShopItemId.SheepSlot = 13`（**追加到末尾，不中间插入** —— Analytics 按数值上报，插中间会错位历史数据）；`CoinWallet` 改四处；`ShopCatalog` 加 1 条。**`ShopPanel` 是数据驱动的，加一条就自动多一行。**
- `ContinueCatalog` + `SheepGameView.ResumeAfterContinue`：限时关续关补 20 秒。

### 差点踩的坑（记录）
- **限时关续关会死循环**：`TickTimer` 判负 → OfferContinue → 复活后 `_ended=false` 但 `_timeLeft` 仍是 0 → 下一帧立刻又判负。必须补时。
- **`MaxSlotBonus` 从 4 压到 2**：`Slots` 节点是 HorizontalLayoutGroup，槽越多每张牌越窄，超过 9 个槽时 80px 的牌会互相压住。配套在 prefab 里加了 `Slot_7/Slot_8` 两个默认 `m_IsActive: 0` 的扩展槽。
- `LayoutSlots` 原本 `i < SlotRoot.childCount ? GetChild(i) : SlotRoot`，槽不够时第 8 张牌会挂到根节点上位置错乱 —— 这是加扩展槽才会暴露的隐藏依赖，一开始完全没想到。

### 预制体（prefab-first，没在运行时搭结构）
- `SheepGameView.prefab`：整体复制 `RemoveButton` 子树（21 块，含 Plus/Mark 角标）→ `SlotButton`（文本「暂存」），挂到 `Footer` 的 `m_Children` 末尾；Footer 的 HorizontalLayoutGroup `m_Spacing` 28 → 20（4 个按钮挤一行）。再复制 `Slot_0` 做出 `Slot_7/Slot_8` 两个隐藏槽。
- 验证：212 块、**无悬空 fileID**、关键节点无重名、`SlotButton: {fileID: ...}` 回填成功、`Slots` 的 Spacing 仍是 8（没被批量替换误伤）。

### 工具
