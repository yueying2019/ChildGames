# 教学关与强制引导（2026-09-25）

三件事：三个玩法的**固定排布教学关（第 0 关）**、**强制手把手引导**、**三星条件展示 + 首次三星满体力**。

## 一、教学关（第 0 关）的定位

| 项 | 教学关 | 正式关 |
|---|---|---|
| 棋盘 | 完全固定，代码内置 | 随机生成 / `.asset` 配置 |
| 星级 | 不评星、不存档 | 评星、计入「X/Y 星」 |
| 解锁 | 不影响进度 | 通关解锁下一关 |
| 体力 | **不扣** | 扣 1 点 |
| 失败 | 不弹续关付费面板，直接重来 | 弹续关 |
| 规则弹窗 | 不弹（教学本身在教） | 首次进玩法弹一次 |

**入口**：主菜单点玩法 → 若该玩法教学关未通关，直接进教学关；否则进选关。
选关列表第一格是教学关（显示「已学会 / 未学习」），点它随时能重看。

**index 约定**：教学关用 `TutorialCatalog.Index = -1` 做哨兵，`LevelIndex` 也取 -1 ——
这样「下一关」走 `LevelIndex + 1` 正好落到正式第 1 关，不用为教学关单独写跳转。
注意三个 Session 的 `StartNextLevel()` 里都把 `IsTutorial = false`，否则会反复进教学关。

## 二、三个教学关的固定排布

数据全部在 `Gameplay/TutorialCatalog.cs`（代码内置，不走 Addressables —— 改引导逻辑本来就要提审）。

### 三消 6×6

整盘走对角线循环 `(x + y) % 4 + 1`，**天然没有任何三连**；只把 `(3,3)` 特设成 1，于是把 `(2,2)` 的 1 换下来就能和 `(1,3)(3,3)` 凑成三连——引导第一步要玩家做的正是这一手。

```
开局 y=3 行:  4 1 2 1 4 1     （无三连）
交换后 y=3 行: 4 1 1 1 4 1     （三连 ✔）
```
`FixedBoard = true` 会跳过开局随机埋「加步 / 金豆荚」，保证局面完全可控。
参数：`ColorCount=4 / MoveLimit=15 / TargetScore=200`（刻意宽松，别让新手在学操作时先尝到失败）。

### 对对消 10×10 里摆 8 张

```
        c3 c4 c5 c6
r=4:    1  1  2  2
r=5:    3  3  4  4
```
两两横向相邻、零转弯可连，第一对 `(4,3)+(4,4)` 就是引导要求点的那一对。
靠 `LianliankanLevelData.IconIds`（新增字段）固定每格图案，`FixedIconAt()` 取值，为 0 的格仍随机。

### 叠叠消 3×3 共 9 张

```
1 2 3
2 3 1
3 1 2
```
**每种图案 3 张 = 3 组**。这里有个硬约束：`ComposeNum=3` 时每种图案的张数必须是 3 的整数倍，
否则消到最后会剩几张凑不成一组、关卡直接卡死。所以是 3×3 而不是 4×4（4 除不尽 3）。
靠 `SheepLevelData.FixedCells`（新增字段）+ `SheepBoardBuilder.PlanFromFixed()` 出 plan。

## 三、强制引导框架

```
玩法 GameView  ──注册 resolver──▶  TutorialDirector（状态机 + 门控）
                                        │
                                        ▼
                                 TutorialOverlay（挖洞遮罩 + 文案 + 跳过）
                                        │
                                        ▼
                                 GuideHighlight（洞内可穿透） + HintFlash.PlayLoop
```

| 文件 | 职责 |
|---|---|
| `UI/Tutorial/TutorialStep.cs` | 一步：高亮坐标、允许的操作、完成信号 |
| `UI/Tutorial/TutorialScript.cs` | 三玩法的步骤脚本（代码内置） |
| `UI/Tutorial/TutorialDirector.cs` | 状态机 + 门控 API + 撤场 |
| `UI/Tutorial/TutorialOverlay.cs` | 挖洞遮罩、底部文案条、跳过按钮 |

### 关键设计

**门控**：`Allowed` 为空 = 不限制（只提示）；非空 = 只允许脚本写的操作。
- 三消 `AllowsPair(x0,y0,x1,y1)`（两端顺序无关）
- 对对消 `AllowsAny(r,c)` 选第一张 + `AllowsPair` 选第二张
- 叠叠消 `AllowsSingle(iconId)` —— **用图案 id 而不是格子索引**：牌一进槽就从棋盘列表摘掉，索引会整体前移，用索引门控第二张就对不上

**挖洞可穿透**：`GuideHighlight.SetPassThrough(true)` 关掉全屏 Catcher，改由四块遮罩吃点击。
洞内点得穿到棋盘，洞外点了给「先按提示操作这几张牌」的提示。多目标时挖一个包住所有目标的大洞。

**完成信号**：玩法不记自己该发什么，完成动作时调 `TutorialDirector.NotifyCurrent()`，由当前步骤自己匹配。

**每份脚本只锁第一步**，第二步放开只做提示：棋盘一旦掉落新块就不可能再按脚本精确演，锁太死会变成「点不动」的挫败感。

**跳过**：记为「已学会」，教学关继续玩，只是不再挡着。

## 四、三星条件展示

`StarCatalog` 新增阈值换算（`ThreeStarMoves / ThreeStarSeconds`），各 Session 重写
`StarConditionText()` / `StarProgressText()` 按自己的评星口径出文案，经 `ResultPayload` 传到结算页。

**只在没拿到三星时显示**（失败页 + 未满星页）：

```
三星：剩余 9 步以上（共 25 步）
本局剩余 4 步
```

口径与 `ComputeStars()` 严格一致（三消配了倒计时就按时间算）。

## 五、首次三星奖励满体力

`GameSessionBase.TryGrantPerfectReward()`：
星级从「历史未满 3」变成「本次 3 星」、且该关没领过 → 体力回满 + Toast + 结算页一行提示。
用 `ProgressRepository.HasPerfectReward/MarkPerfectReward`（新增 `LianPerfect/SheepPerfect/Match3Perfect` 三个 `List<int>`）去重，同一关重复打三星不再发。

**顺序敏感**：必须在 `RecordStars()` **之前**调用 —— `RecordStars` 只升不降，写完就分不清是不是首次了。

## 六、自检与验证清单

自检脚本：`Tools/` 下可复用的临时校验（括号配平 + 契约成员 + 接入点 + 棋盘可解性），本次结果全绿：
开局无三连 ✔ / 交换后成三连 ✔ / 叠叠消每种图案都能被 3 整除 ✔ / 对对消 8 张成对且首对相邻 ✔。

真机要验的：
1. 第一次进每个玩法是否直接进教学关，遮罩是否只挖出目标格子、洞内点得动、洞外点不动
2. 三消按提示交换后是否自动进入第二步；跳过按钮是否生效
3. 教学关通关 → 「下一关」是否到第 1 关（不是第 2 关，也不是又进一次教学）
4. 失败页/未满星页是否显示三星条件；首次三星是否体力回满且只发一次
